# frontend — the Wincent website (Next.js)

The published site. Part of the `website/` block; see [../README.md](../README.md) for how
`build/` (the Python JSON builders) feeds this app.

Where its data comes from, in the order the app prefers it:

- **Railway Postgres**, at render time and at request time. `lib/data.ts` →
  `corpusCensus.ts` reads the ETL's own record of the corpus for the headline
  figures; `lib/intelligence/corpus.ts` dynamically imports `pg` for the
  instrument and gate lookups behind `/brief`.
- **`public/data/*.json`** (generated by `../build/`), which is the committed
  fallback when Postgres is unreachable — not the primary source.
- **`fund-processes/*.md`** and **`contracts/`**, read from `process.cwd()` at
  request time by the memo pipeline.

## Run

```bash
npm run dev        # dev server at http://localhost:3000
npm run build      # next build (prebuild runs ../build/build_site_data.py --check)

npm run check      # EVERYTHING free: types, unit tests + coverage, vocabulary
                   # contract, 12-archetype regression, payload budget,
                   # dependency audit. This is what CI runs — if it passes
                   # here it passes there. No API calls, no spend.
npm run test       # just the unit tests
npm run health     # operational digest from Postgres: errors, degradations,
                   # spend against the daily ceiling. Exits non-zero when
                   # something needs attention, so it can be a cron.
npm run vocab      # regenerate data/vocabularies.json after changing any
                   # option list in types.ts — the Python ETL reads that file,
                   # and check_vocabularies fails if it is stale.
npm run trace      # free: which instruments reach the writer, per archetype
npm run board      # free: score every brief ever generated against known defects
npm run bench      # COSTS MONEY: real companies through the full pipeline
```

`npm run build`'s `prebuild` hook fails if the JSON in `public/data/` is stale versus
`data/db.sqlite` — regenerate it with `make data` from the repo root first.

## Layout

Publicly the site is three pages plus a privacy notice. Every route in the tree
is listed here; if it is not below, it does not exist.

```
app/
  page.tsx                  home (KPIs, Europe map, taxonomy network)
  about-public-capital/     the narrative case for public capital
  brief/                    the founder-facing brief (+ the LLM intelligence panel)
    preview/                DEV ONLY (notFound() in production): renders the real
                            Memo from a recorded fixture so `npm run preview:pdf`
                            can print the stylesheet and it can be read back
    preview/questions/      "  the round-2 question screen
    preview/withheld/       "  the withheld-row surface
  privacy/                  what is retained and for how long, read from the
                            constants that enforce it (RETENTION_DAYS)
  api/
    intelligence/route.ts         the streamed memo (NDJSON over a ReadableStream)
    intelligence/intake/route.ts  the adaptive round-2 question screen
    intelligence/verdict/route.ts the instant, model-free eligibility screen
    intelligence/region/route.ts  region options for the founder's countries
    guards/route.ts               the guard verdict feed
components/                 shared UI (nav-bar, charts, europe-map, channels-graph,
                            funding-ladder, immersive, finding, image-slot,
                            euro-journey, ui/ primitives)
lib/
  intelligence/             the /brief feature: pipeline · corpus · types · panel.
                            ── START WITH lib/intelligence/ARCHITECTURE.md ──
                            Our code builds the subset, an LLM ranks it, the
                            deterministic score is subset-builder + fallback +
                            control. That file also lists every ranking route
                            already measured dead, so nobody re-buys one.
  corpusCensus.ts corpusFigures.ts corpusProse.ts data.ts format.ts
  palette.ts utils.ts verifiedAwards.ts
scripts/                    guards (check_*), measurement harnesses, emitters
  archive/                  measurement scripts for CLOSED routes, each with a
                            one-line note on what it bought. Nothing runs them;
                            they exist so an answered question is not re-bought
contracts/                  the memo's output spec; rule IDs shared by the prompt
                            and by scripts/check_contracts.ts
fund-processes/             per-instrument briefs the intelligence route reads at runtime (process.cwd)
public/data/                the committed JSON fallback (written by website/build/)
```

## Notes

- **This is not a static export.** `next.config.ts` has no `output: "export"`,
  and it says why: the API routes are server-side Route Handlers that keep the
  Anthropic key off the client. All five `app/api/**` routes are
  `dynamic = "force-dynamic"` on the Node runtime. The pages are prerendered and
  revalidated hourly (`export const revalidate = 3600`), not frozen at build
  time — they state corpus figures that must follow the database.
- A stale `out/` directory on a dev machine is a fossil of the era when this
  WAS a static export. Nothing builds it now; it is gitignored and safe to delete.
- `fund-processes/` and `public/data/companies_index.json` are force-traced into the
  serverless function in `next.config.ts` (`outputFileTracingIncludes`) because the route
  reads them from disk at runtime.
- Don't add a barrel that re-exports the `"use client"` intelligence panel together with the
  server-only `lib/intelligence/corpus.ts` (fs reads) — it breaks under Turbopack. Import directly.
- This is a pinned, non-standard Next.js build — see [AGENTS.md](AGENTS.md) before editing.
